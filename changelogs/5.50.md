# 5.50.0
Released 24th September 2026.

This is a minor feature release for Minecraft: Bedrock Edition 1.26.50 (display version 26.50). It is the first release of the EraseMC fork, now called **Erase-PocketMine-MP**, and adds support for older Minecraft versions alongside the current one.

**Plugin compatibility:** Plugins for previous 5.x versions will run unchanged on this release, unless they use internal APIs, reflection, or packages like the `pocketmine\network\mcpe` or `pocketmine\data` namespace.
Do not update plugin minimum API versions unless you need new features added in this release.

**WARNING: If your plugin uses the `pocketmine\network\mcpe` namespace, you're not shielded by API change constraints.**
Consider using the `mcpe-protocol` directive in `plugin.yml` as a constraint if you're using packets directly.

## General
- The server software is now called Erase-PocketMine-MP. It is maintained by the EraseMC organization as an independent fork of PocketMine-MP and NetherGames' multi-version work; namespaces and the plugin API are unchanged.
- Minecraft: Bedrock Edition clients from 1.16 to 1.18 can now join, in addition to 1.20.0 and later:

| Minecraft: Bedrock Edition | Status |
| --- | --- |
| 1.16.100 – 1.16.101 | Supported |
| 1.16.0 – 1.16.40, 1.16.200 – 1.16.221 | Implemented, but not yet tested with real clients; blocked by default |
| 1.17.0 – 1.17.41 | Supported |
| 1.18.0 – 1.18.33 | Supported (1.18.30 – 1.18.33 have not been tested with a real client) |
| 1.19.x | Not supported yet |
| 1.20.0 – 1.26.50 | Supported |

- The startup log now lists the Minecraft versions allowed to join.

## Configuration
- Added the `multiversion` section to `pocketmine.yml`. It controls which of the supported versions may join:
  - `minimum-version` and `maximum-version`: the lowest and highest allowed version, e.g. `"1.16.100"`. Patch releases are matched to their protocol, and the new display scheme (`"26.50"`) is accepted.
  - `blocked-versions`: versions which may never join. Entries may be a Minecraft version (`"1.16.200"`), a whole release line (`"1.16"`) or a protocol number (`422`). By default this blocks the 1.16 releases which have not been tested with a real client, so only 1.16.100 and 1.16.101 may join from the 1.16 line. Servers whose `pocketmine.yml` has no `multiversion` section use the same default.
  - `kick-message`: a custom message for players whose version may not join; empty shows the game's standard "outdated client" screen.
  - Settings which cannot be understood are reported as warnings at startup and ignored.
- `pocketmine.yml` has been reorganised into titled sections with clearer comments. No existing setting or default value was changed.

## Fixes
- Legacy login chains which are not signed by a trusted Mojang root are no longer treated as Xbox Live authenticated.
- Clients before 1.19.10 now receive their abilities, permissions and flight state through the legacy adventure settings, and their flight toggles are applied.
- 1.17 clients no longer crash after spawning because of a player skin encoded in the 1.17.30 layout.
- Blocks broken by 1.17 clients are now broken on the server as well (fixes missing drops).
- Block recipe ingredients sent to 1.17 and 1.18 clients now use the correct block variant; the block data maps used for them did not match those versions' block palettes.
- The creative inventory of older clients no longer contains placeholder blocks for items their version does not have.
- Older clients hitting an item frame are no longer disconnected.

## API
### `pocketmine`
- The following API methods have been added:
  - `public Server->getVersionRestrictions() : \pocketmine\network\mcpe\VersionRestrictions`

### `pocketmine\network\mcpe`
- The following classes have been added:
  - `VersionRestrictions` - the Minecraft versions allowed to join, as configured in the `multiversion` section of `pocketmine.yml`

### `pocketmine\network\mcpe\cache`
- `StaticPacketCache->getAvailableActorIdentifiers()` now accepts an optional `int $protocolId` parameter.

### `pocketmine\network\mcpe\convert`
- The following API methods have been added:
  - `public static BlockStateDictionary::loadLegacyPaletteFromString(string $blockPaletteContents) : list<BlockStateData>`
  - `public static BlockStateDictionary::loadFromPalette(list<BlockStateData> $palette, string $metaMapContents) : BlockStateDictionary`
  - `public BlockStateDictionary->lookupStateIdFromOriginalIdMeta(string $id, int $meta) : ?int`
  - `public BlockTranslator->getLegacyNetworkPalette() : ?string`

## Internals
- Legacy protocol support is split into per-version profiles, documented with their sources and verification status in `docs/legacy-protocol`.
- Legacy Minecraft data (block palettes, item tables, entity and biome lists) is restored byte-for-byte from historical PocketMine-MP data. Block data maps for 1.16 to 1.18 are generated by the new `tools/generate-block-state-meta-map.php`.
- The `pocketmine.yml` property constant generator no longer emits constants for list entries.
- Release builds use the `erasemc/bedrock-data` package.
