# 5.51.0
Released 29th October 2026.

This is a minor feature release for Minecraft: Bedrock Edition 1.26.60 (display version 26.60). It merges the upstream NetherNet transport (upstream 5.50) and Bedrock 1.26.60 support (upstream 5.51) into Erase-PocketMine-MP while keeping every older version which could join before.

**Plugin compatibility:** Plugins for previous 5.x versions will run unchanged on this release, unless they use internal APIs, reflection, or packages like the `pocketmine\network\mcpe`, `pocketmine\nethernet` or `pocketmine\data` namespace.
Do not update plugin minimum API versions unless you need new features added in this release.

**WARNING: If your plugin uses the `pocketmine\network\mcpe` or `pocketmine\nethernet` namespace, you're not shielded by API change constraints.**
Consider using the `mcpe-protocol` directive in `plugin.yml` as a constraint if you're using packets directly.

## General
- Added support for Minecraft: Bedrock Edition 1.26.60 (display version 26.60).
- Clients from 1.16 to 1.18 and from 1.20.0 to 1.26.60 can join:

| Minecraft: Bedrock Edition | Status |
| --- | --- |
| 1.16.100 – 1.16.101 | Supported |
| 1.16.0 – 1.16.40, 1.16.200 – 1.16.221 | Implemented, blocked by default (not tested with real clients) |
| 1.17.0 – 1.17.41 | Supported |
| 1.18.0 – 1.18.33 | Supported (1.18.30 – 1.18.33 have not been tested with a real client) |
| 1.19.x | Not supported |
| 1.20.0 – 1.26.60 | Supported (1.26.60 tested with protocol clients, not yet with the game) |

- Added support for the NetherNet (WebRTC) network transport. Clients prefer NetherNet when the server offers it and fall back to RakNet otherwise.
  - NetherNet needs the [`ext-webrtc`](https://github.com/axolotl-pm/ext-webrtc) PHP extension (`^0.3.1`). Without it the transport is skipped with a warning and RakNet still starts.
  - Clients before 1.26.50 can only join through RakNet, so RakNet stays enabled by default.
  - The built-in signaling opens a TCP port (the server port unless configured otherwise) and LAN discovery on UDP 7551.
- RakNet and its settings (`network.upnp-forwarding`, `network.max-mtu-size`, `network.enable-encryption`) are deprecated upstream; a warning is logged when RakNet starts.

## Configuration
- Added the `transport` section to `pocketmine.yml`:
  - `transport.name`: active transports as a comma-separated list, `nethernet,raknet` by default.
  - `transport.nethernet`: identity key file, identity domain, ICE (UDP mux, port range, MTU, advertised addresses, STUN/TURN servers) and the built-in signaling (port, TLS, reverse proxy).

## Gameplay
- Fire, chorus plants and redstone wire now keep their connection states as real block states. Clients before 1.26.60 receive the matching state of their own palette.

## Fixes
- 1.26.10 clients logging in without Xbox Live (self-signed) are no longer disconnected with "Expected exactly 3 JWT parts"; their OpenID token is now accepted.
- Item stack request actions of clients before 1.18.10 no longer mistake the lab table and beacon payment actions for the bundle actions.
- Map data sent to clients before 1.19.20 no longer contains a map origin, which they don't expect.
- Item interactions in `PlayerAuthInputPacket` are now decoded completely for every version (upstream fix); the 1.17-only workaround is no longer needed.

## API
### `pocketmine\event\player`
- Added `PlayerIdentityVerifyEvent` (upstream), called after the login and transport identity were verified and before the player is created.

### `pocketmine\network`
- Added the `Transport`, `TransportIdentityKey` and `TransportIdentityException` types and `Network->registerTransport()`, `getTransport()`, `getTransports()`, `activateTransport()` and `getActiveTransports()` (upstream).
- `Network->registerInterface()`, `upnp\UPnP` and `upnp\UPnPNetworkInterface` are deprecated (upstream).

### `pocketmine\block`
- `ChorusPlant` and `Fire` implement `HorizontalConnectable`; `RedstoneWire` has `getConnection()` and `setConnection()`; added `RedstoneSignalEmitter` and `RedstoneWireConnectionType` (upstream).

## Internals
- BedrockProtocol follows the upstream conversion of name, ordinal and integer constant types to enums (`GameMode`, `PlayerPermissions`, `CommandPermissions`, `CompressionAlgorithm`, `InputMode`, `PlayMode`, `InteractionMode` and others). The legacy `AdventureSettingsPacket` uses the same enums.
- `CommonTypes::getItemStackWrapper()` and `putItemStackWrapper()` no longer take a `$networkDescriptor` flag; packets which switched to the descriptor format in 1.26.30 call `getNetworkItemStackDescriptor()` and `putNetworkItemStackDescriptor()` instead.
- `TransactionData::decode()` and `encode()` replace the separate transaction and auth input methods, with `$authInput` and `$legacyHasItemStackIds` parameters.
- 1.26.40 clients, which send the same protocol number as 1.26.44, are told apart by their game version (upstream).
- Protocols with identical block data share one block state dictionary; old palettes fall back to the default values of block properties which were added later (upstream), before the existing fixed-property fallback.
- Added a dependency on `axolotl-pm/nethernet` (`^0.3.1`).
