The 1.16.10 and 1.16.40 rows are inferred: PMMP 3.14 (407 only) and 3.15 (408 only) covered those client releases without a protocol update. Live tests must confirm them. Preview protocols are out of scope. Clients sharing a protocol ID share the same wire profile. Work happens on `feature/legacy-1.16` in PocketMine-MP, BedrockProtocol and BedrockData; profiles stay outside `ACCEPTED_PROTOCOL` behind an opt-in local trial gate until the owner has verified them on real clients.

## Compatibility boundaries

- **1.16.0 / 1.16.20 (407/408):** the server sends the complete block palette in StartGame and defines runtime IDs by its order. Items use legacy numeric IDs with legacy damage values; there is no creative content packet (creative items are an inventory window) and crafting uses legacy inventory transactions. 1.16.20 changed block-state data but no packet layouts.
- **1.16.100 (419):** client-side block palette, item runtime-ID table in StartGame, `CreativeContentPacket`, item stack requests, player movement settings, new resource-pack stack experiments, and many packet changes.
- **1.16.200 (422), 1.16.210 (428), 1.16.220 (431):** incremental packet changes (stack responses, auth input, commands, camera shake, item stack layout). 1.16.220 added the block runtime ID to item stacks; earlier profiles encode block items only by legacy damage.
- **1.16.220 → 1.17.0 (440):** the boundary already implemented by our 1.17 support must be reversed for every field 1.17.0 added.

## Data plan

- Block palettes: PMMP `required_block_states.nbt` at BedrockData `43edcfd` (1.16.0) and `afc885c` (1.16.20), byte-for-byte, sent in StartGame for 407/408. `canonical_block_states.nbt` at `14f4a76` (1.16.100, identical at `4e58a3c` for 1.16.200) and `989e02a` (1.16.210, identical at `f31a33c^` for 1.16.220).
- Item tables: `required_item_list.json` at `14f4a76` (identical for 1.16.100/200/210) and `required_item_list-1.16.220.json` at `f31a33c^`; legacy item ID map for 407/408.
- Block-state meta maps are indexed by palette position and are required for legacy-damage block items. They are generated per palette from the legacy ID/meta mapping instead of borrowing a newer map.

## Acceptance gate

Login, encryption, resource packs, StartGame, chunks, movement, block break/place, inventory, creative inventory, crafting, containers, entities and skins, commands, flight and reconnect on a real client for every profile. Only then are the profiles admitted to `ACCEPTED_PROTOCOL`.
