# Bedrock Edition 1.17 legacy support

## Stable profile matrix

| Stable client releases | Protocol | Profile | Live test |
| --- | ---: | --- | --- |
| 1.17.0, 1.17.1, 1.17.2 | 440 | `1.17.0` | 1.17.0 joined; gameplay fixes awaiting retest |
| 1.17.10, 1.17.11 | 448 | `1.17.10` | awaiting 1.17.11 |
| 1.17.30, 1.17.32, 1.17.33, 1.17.34 | 465 | `1.17.30` | awaiting 1.17.34 |
| 1.17.40, 1.17.41 | 471 | `1.17.40` | awaiting 1.17.41 |

1.17.20 was a preview, not a stable release. Unlisted preview protocols are out of scope. Clients sharing a protocol ID share the same wire profile, but their patch versions still need smoke tests where feasible.

## Current implementation and gate

- Four protocol IDs exist in BedrockProtocol but are not in `ACCEPTED_PROTOCOL`. For a single local test, set `ERASEMC_TEST_1_17_PROTOCOL` to 440, 448, 465 or 471; the same value selects the discovery advertisement. Do not enable this gate on public servers.
- Byte-for-byte historical canonical block-state and required-item snapshots were restored in BedrockData for all four profiles. The 1.17.40 palette is the unversioned historical 1.17.40 canonical palette.
- Packet boundaries restored from preserved PocketMine history include 1.17.0 versus 1.17.10 resource-pack/command/title fields, 1.17.30 education/volume/animation/crafting fields, 1.17.40 sub-chunk response, and the 1.18.0 StartGame checksum and sub-chunk hash field. The pre-1.17.30 skin geometry engine version may be absent in login JSON.
- Pre-1.18 chunks use old overworld height and two-dimensional biomes; zero-bit palettes are expanded for 440/448 and natively encoded from 465 onward. The sound ID is clamped to the historical 1.17 `UNDEFINED` ID 330.
- A real protocol-440 client trial found that wire movement value 2 stalls before spawn: in 1.17 it represents rewind-based movement, not modern V3. Profile 440 now advertises value 1, which reached `joined the game`. Intermittent `Locating Server` timeouts remain unresolved.
- Live gameplay with the Windows package `MinecraftUWP_1.17.2.0` (executable reports `1.17.0.2`) exposed missing block animation/drops and unusable inventory. `PlayerAuthInputPacket` carries flag-gated interaction and block actions in this mode; the earlier assumption that all 1.17 clients omit these fields was wrong. The action-ID decoder was corrected. A later block-break attempt still kicked on bogus action type 280 because the 1.17 item-interaction payload was only partly consumed; BedrockProtocol `a18da1b` now reads the complete legacy transaction before block actions. Live retest pending.
- A newer 1.17.2.1 client joined on Essential but crashed during our pre-spawn sequence. Comparison found our StartGame sent the post-1.21.80 `locatorbar` game rule to 1.17. The rule is now limited to supported protocols, matching Essential. Whether this fixes the client crash requires live validation; no crash cause is claimed yet.
- On the next live attempt the same client still crashed before acknowledging spawn. An opt-in `ERASEMC_TRACE_1_17=1` disconnect diagnostic now records a bounded, payload-free history of packet types, current handler/stage, queued chunks, transport batches and pending queues for all four 1.17 profiles. This can narrow the failure stage but cannot prove client receipt or causality. Do not share full `debug.level: 2` logs; they may contain packet payloads.
- Missing historical block-item, block-state-meta and item-tag datasets currently use documented newer fallbacks. They are not proven version-accurate. Rendering and recipe correctness must be assessed in live clients; these gaps are release risks, not an assertion of complete support.

## Verification checklist

For each of 440/448/465/471: startup and server-list discovery, authenticated login, world spawn and chunks, movement and fall, block break/place, inventory hotbar and chest, crafting, commands, entity interaction, dimension travel, skin visibility, reconnect, and server log free of packet errors. A pass at login alone is insufficient. Record client build and observations here before promotion to `stable`.
