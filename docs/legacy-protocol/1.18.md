# Bedrock Edition 1.18 legacy support

Preview protocols are intentionally excluded. Patch releases sharing a protocol profile use the same wire codec and data snapshot.

## Compatibility boundaries

- All stable 1.18 profiles use RakNet protocol 10 and send a zlib-compressed `LoginPacket` as the first MCPE packet. They use the legacy branch already restored for pre-1.19.30 clients.
- 1.18.0 introduced negative-Y terrain and expanded chunk columns.
- 1.18.10 revised the sub-chunk request system and added related packet layouts and stack-request actions.
- 1.18.30 changed StartGame/LevelSettings-era structures, command parameter IDs, AddPlayer, volume entities, particles and several packet types.
- Each profile requires its own canonical block-state and item-runtime snapshots. Newer data cannot be substituted safely.

## Sources of truth

- Historical PMMP commits: BedrockProtocol `040a883`, `e9b1596`, `76cf00a`; PocketMine-MP `8620e67d8`, `325131dd3`, `c085bf0db`; BedrockData `3913650`, `da48a0f`, `f74589f`.
- Mojang Bedrock protocol documentation and the 1.18.10 sub-chunk request-system specification.
- Nukkit-MOT protocol constants and codecs, used as an independent cross-check.
- Essential's multi-version implementation, used to identify modern integration points; historical PMMP remains authoritative for its own codec behaviour.

## Acceptance gate

A profile must not be added to `ProtocolInfo::ACCEPTED_PROTOCOL` until login, encryption, StartGame, chunk loading, inventory, crafting, entities, commands, movement, block interaction and reconnect have been exercised with a real client from that profile.
