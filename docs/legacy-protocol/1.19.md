## Facts established before implementation

### Transport and login bootstrap

This is the compatibility boundary which caused PocketMine to remove pre-1.20 support in 2023.

| Client profile | RakNet acceptor version | First MCPE packet batch | Bootstrap action |
| --- | ---: | --- | --- |
| 1.19.0 through 1.19.21 | 10 | zlib-compressed `LoginPacket` | Decode first compressed batch, validate protocol, then retain legacy compression. |
| 1.19.30 through current | 11 | uncompressed `RequestNetworkSettingsPacket` | Negotiate network settings, then enable compression before `LoginPacket`. |

The original PocketMine implementation accepted both RakNet versions 10 and 11. Its later removal commit replaced the dual acceptor with `SimpleProtocolAcceptor(11)` and replaced the legacy-first login state with the new session-start state. The modern core must restore the capability through an explicit, bounded bootstrap handler rather than through a permissive decompression fallback.

### Wire-format boundaries within 1.19

The 1.19 profiles cannot share a single generic serializer. The authoritative Mojang changelogs and PocketMine's preserved versioned implementation identify at least these boundaries:

| Boundary | Required compatibility work |
| --- | --- |
| 527 -> 534 | `UpdateAbilitiesPacket`/`UpdateAdventureSettingsPacket`, `AddActorPacket`, `AddPlayerPacket`, level settings, skin/client data. |
| 534 -> 544 | maps, modal forms, chunk publisher, attributes with modifiers, feature registry, start-game and level-settings fields. |
| 544 -> 554 | network settings and compression negotiation, recipe descriptors, text, structure data, inventory transaction format. |
| 554 -> 557 | synced actor properties, network throttle settings, item descriptor representation, metadata enum shifts. |
| 557 -> 560 | client input locks, entity flags, container/UI IDs, structure template operations. |
| 560 -> 567 | abilities and action flags, command request, crafting/smithing transform data, level events/sounds. |
| 567 -> 568 | 1.19.62 changed skin serialization without changing its login protocol; dispatch must use `GameVersion`, not protocol number alone. |
| 568 -> 575 | player auth analog movement, unlocked recipes, camera packets, ability and metadata shifts. |
| 575 -> 582 | hashed block network IDs, subchunk version 9, compressed biome definitions, trim data, sign editor, smithing trim data. |

### Versioned data required

The historical `BedrockData` tree retains the exact released data assets removed in commit `285cdbb07a8fb188972e9564bf2b9ece11670452`. The versioned profile loader needs these data families:

- canonical block states and block-state meta maps for 1.19.10, 1.19.40, 1.19.50, 1.19.63, 1.19.70, and 1.19.80;
- required item lists for 1.19.0, 1.19.40, 1.19.50, 1.19.63, 1.19.70, and 1.19.80;
- legacy block-id-to-item-id maps for the same applicable breakpoints; and
- `r12_to_current_block_map` assets for the 1.19.63, 1.19.70, and 1.19.80 block palettes.

These binary data assets must be restored byte-for-byte from history and verified by object hash. Do not regenerate or hand-edit them.

## Implementation lanes

1. **Protocol foundation** — add named stable constants/profiles and tests; restore all packet layout gates removed after 1.19.80.
2. **Transport bootstrap** — accept RakNet 10/11, make the first-batch state deterministic, negotiate only where supported, and preserve modern behaviour.
3. **Versioned data translation** — restore historical BedrockData assets and connect them to per-profile block/item/recipe translators.
4. **Gameplay packet paths** — abilities, entity metadata, inventory, crafting, chunk, biome, commands, forms, sounds, particles, signs, and maps.
5. **Verification** — codec fixtures, data hashes, profile-boundary tests, then real unmodified clients for every stable profile group.

## Release gates

A row in the target table may be marked **ready** only after all gates below pass.

- The client completes transport/login/resource-pack/spawn flow without a protocol disconnect.
- Chunks load with the correct palette; moving between chunks, breaking and placing blocks, and block entities work.
- Creative inventory, survival inventory, crafting, armour/offhand, item use, and transactions work.
- Player/entity spawn, movement, metadata, skins, sounds, particles, chat, commands, forms, and respawn work.
- Codec and asset-integrity tests cover the profile and all adjacent boundaries.
- A tested, unmodified client build is recorded in `SESSION_LOG.md` with date, platform, and result.

## Current status

The protocol foundation is in progress. Named constants, several codec-boundary batches, and the legacy packet-pool entry are present in `BedrockProtocol`. Historical 1.19 assets have been restored and hash-checked in `BedrockData`; core translators and Composer dependencies now target the feature branches. The dual transport bootstrap has an implementation and unit tests, but those tests, the remaining gameplay packets, and real-client validation remain. No client profile has yet been marked supported or ready.
